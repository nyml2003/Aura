# 约束

本文档为已确认的**技术约束**清单，技术设计必须在此范围内。

---

## 0. 运行环境（前提）

- **服务器**：2 核 2G，单机单实例。
- **部署**：Docker 编排，Nginx 反向代理；不引入 Node 常驻进程；首屏数据拼装在 Go 内（BFF 式思路）。

---

## 1. 架构与部署

| 类别 | 约束 | 说明 |
|------|------|------|
| 架构 | **先做单体，区分网关层** | 保留后续拆微服务可能；网关层做鉴权、限流、路由与分发，业务在各自模块。 |
| 部署 | **Docker Compose + Nginx** | Nginx 做反向代理与静态资源；Go 提供页面与 API，不直接对外提供静态文件。 |
| 代码组织 | **Monorepo** | 前后端代码同一仓库；文档可单独仓库。 |

---

## 2. 后端与 API

| 类别 | 约束 | 说明 |
|------|------|------|
| 语言 | **Go** | 后端用 Go 实现。 |
| API | **首屏：布局+页面数据同时下发（Go 内 BFF 式拼装）；其余直调 REST** | 首屏不单独请求接口，由 Go 按页拼装模块数据、内联进 HTML 一次返回；模块拆分与拼装逻辑在 Go 内（BFF 式思路），不引入 Node、不 SSR。其余「加载更多」、分页、详情等直调 REST。URL/路由/跳链由研发设计，链接由后端下发**完整 URL**，前端不拼链接。 |

---

## 3. 前端

| 类别 | 约束 | 说明 |
|------|------|------|
| 架构 | **Monorepo + 多 npm 包** | 前端为 Monorepo（如 pnpm workspace），内含多个包：如**请求 SDK**（交互与非首屏数据请求）、**页面通用依赖**（如从 window 解析数据并渲染）；各页面应用依赖上述包。 |
| 技术栈 | **React + MPA**（首屏方案可用 Solid） | 多页应用，每页隔离；链接与状态依赖后端下发的跳链与参数。首屏方案若采用 Solid，见 05/06。 |
| 职责 | **视图层尽量只有业务** | 请求、状态、工具等抽离并单测；视图层不覆盖单测。 |

---

## 4. 内容与数据

| 类别 | 约束 | 说明 |
|------|------|------|
| 内容模型 | **Item 抽象** | 内容不只有文章，还有小游戏/互动 demo 等；统一为「item」，首页为推荐 item（手动打标）+ 瀑布流，列表为分页查询。 |
| 内容存储 | **先以文件为主，无独立 DB** | 正文与元数据存 Git 或磁盘；具体方案见 03 文档。 |
| 媒体存储 | **成本优先：同机目录** | 图片、附件先同机目录，URL 可配置前缀便于后续 CDN/OSS；视频用外链嵌入，不自建。 |
| 搜索 | **自建** | 评论、统计、搜索均自建，不接第三方。 |

---

## 5. 安全与权限

| 类别 | 约束 | 说明 |
|------|------|------|
| 权限 | **管理员支持 RBAC** | 角色与权限可扩展。 |
| 内容 | **支持私密/草稿** | 仅管理员可见或未发布状态。 |
| 登录 | **隐藏登录入口** | 约定入口，不对外暴露。 |

---

## 6. 性能与体验

| 类别 | 约束 | 说明 |
|------|------|------|
| 首屏与关键路径 | **从输入 URL 到页面不抖动为止约 100ms** | 产品「流畅」验收标准：首屏一次到位，不做骨架屏、不采用 SSR；布局与页面数据同时下发，由 Go 内 BFF 式模块拼装后内联进 HTML，实现方式见 04 可行性评估。 |

---

## 7. 运维与质量

| 类别 | 约束 | 说明 |
|------|------|------|
| 日志 | **异步写、可过期、可排查** | 支持日志过期，又支持问题排查；最好有单独运维用前后端。 |
| 健康检查 | **提供健康检查接口** | 与部署/运维配合。 |
| 发布 | **接入 CI** | 发布方式接入 CI。 |
| 停机 | **尽量零停机** | 可接受短暂停机，希望趋近零停机。 |
| 单测 | **除视图层外覆盖** | 单元测试除视图层外都要覆盖；视图层尽量只有业务，其他抽离并单测。 |
| 契约 | **OpenAPI** | 接口采用 OpenAPI 契约（首屏无独立 REST 时，可单独约定首屏数据结构）。 |

---

## 8. 其他

- 产品需求定义**有哪些页面、每页做什么、体验指标**，不规定 URL/路由。
